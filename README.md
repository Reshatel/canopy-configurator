# Конфігуратор навісу

Параметричний конфігуратор дерев'яного навісу на чистому **Three.js r180**, без 3D-фреймворків
(React Three Fiber не використовується). UI — звичайний DOM.

**Демо:** _(посилання)_

Конструкція збирається алгоритмічно з 13 деталей комплекту: код рахує кількість колон, довжини
балок, крок крокв і вставок, розкладку настилу й покриття, і перебудовує сцену на кожну зміну
параметра. Жодна деталь не є «розтягнутою моделлю всього навісу».

## Запуск

```bash
npm start
# http://localhost:5173
```

Підійде будь-який статичний сервер із кореня проєкту (`python3 -m http.server`, `npx serve`).
Потрібен саме HTTP: через `file://` браузер блокує ES-модулі та `fetch` моделі.

### Чому немає кроку збірки

ТЗ вимагає 3D виключно на Three.js без фреймворків, а UI — на вибір. За таких умов бандлер нічого
не дає: проєкт складається з ES-модулів, які браузер вантажить напряму, а Three.js r180
зафіксований у `vendor/three` (`build/` + чотири аддони) і підключений через `importmap`.

Наслідок: `git clone` і будь-який статичний хостинг — і демо працює. Без `npm install`, без
`node_modules`, без несподіванок з версією бібліотеки у рев'ювера. Деплой на Vercel — це
завантаження статики, конфіг у `vercel.json`.

## Структура

```
index.html            importmap + розмітка панелі параметрів
server.mjs            статичний сервер на вбудованих модулях Node
assets/               Canopy_Models.glb — усі 13 деталей з матеріалами і UV
src/config.js         імена деталей, діапазони параметрів, розміри вузлів
src/canopy/layout.js  розкладка конструкції: чисті обчислення, без залежності від three
src/canopy/Canopy.js  розкладка → InstancedMesh на кожен тип деталі
src/PartLibrary.js    завантаження GLB, запікання трансформацій нод у геометрію
src/Viewer.js         рендерер, освітлення, тіні, оточення, OrbitControls, вписування в кадр
src/ui/ParamPanel.js  панель параметрів і зведення по деталях
src/ui/Inspector.js   підсвітка деталі під курсором, підпис, фокус по подвійному кліку
vendor/three/         Three.js r180, зафіксована версія
```

`layout.js` повертає плоский список розміщень `{ part, position, rotationY, scale }`.
`Canopy` групує його за типом деталі й будує по одному `InstancedMesh` на тип, тому перебудова
сцени на кожну зміну параметра — це лише перезапис матриць інстансів, без клонування мешів.

Геометрія й матеріали належать `PartLibrary` і спільні для всіх інстансів — при перебудові
звільняються тільки буфери інстансів.

На 8×8×8 м сцена складається з ~614 деталей, які рендеряться 13 викликами.

## Керування

Обертання — ліва кнопка, переміщення — права або два пальці, зум — колесо (до курсора).
Подвійний клік наводить камеру на деталь. При наведенні деталь підсвічується, а поруч
з курсором показується її назва, переріз і фактична довжина — це водночас найшвидший спосіб
перевірити розкладку. Чекбокс «Тільки каркас» ховає фризи, настил, покриття і профіль.

## Параметри

Ширина, глибина, висота — **2…8 м**, крок 0.05 м. Габарити задаються **по зовнішніх сторонах
колон**; висота — це висота колони, повна висота до верху даху показана в зведенні.

Профіль периметру — три варіанти з комплекту завдання:

| Варіант | Деталі | Кут |
|---|---|---|
| Суцільний 67×134 | `profile_canopy_perimeter_closed` | підрізання встик |
| Зкруглений R20 | `roof_edge_1m` | `roof_edge_corner` |
| Прямий зі скосом | `roof_edge_1m2` | `roof_edge_corner2` |

Усі три ставляться в рівень з верхом зовнішнього фриза, тому силует даху не змінюється —
змінюється тільки форма канта. Колір профілю — три градації з `Edges.gltf`
(M_RoofEdge_1/2/3); матеріал клонується з `aluminium` один раз на колір і кешується.

## Правила складання

Джерело розмірів — документація до завдання, усі деталі використовуються в рідних пропорціях,
масштабується лише довжина (моделі для цього й підготовлені).

| Вузол | Правило |
|---|---|
| Колони `balk_150x150x2200` | по периметру прямокутника, зовнішні грані в габарит; проміжні колони при прольоті > 3 м; висота — масштаб по Y |
| Кутові балки `balk_corner` | пайвот збігається з пайвотом колони, по верху колони, в обидві сторони вздовж периметра |
| Кільцеві балки `balk_150x150x1000` | по верху колон; балки довгої сторони приходять встик до коротких і не заходять у них геометрією; ряд ріжеться на відрізки ≤ 2.5 м |
| Нижній фриз `Lodge_20x200x1000` | винос 180 мм за край колони, низ на 100 мм вище верху колони |
| Верхній фриз | зміщений на 20 мм назовні й на 100 мм вище внутрішнього |
| Короткий брус B `lodge_150x50x1000` | крокви на ребро (150 у висоту), упоперек коротшого прольоту, крок ≤ 500 мм, по осі кожної колони; торці по центру колон (для 3×5 м — 11 шт.) |
| Довгий брус C | той самий переріз плазом (150 у ширину, 50 у висоту), суцільний уздовж довгих сторін, центром по зовнішній грані кільцевої балки — половина ширини звисає за край |
| Вставки `lodge_150x50x200` | у торцевих смугах, заповнюють проміжок між крайньою кроквою і внутрішнім фризом, крок ≤ 600 мм |
| Настил `Lodge_20x190x1000_bevel` | лягає на внутрішній фриз і крокви; дошки по 1 м із розбіжкою стиків через ряд, добірна підрізається по ширині |
| Покриття `ruberoid_1000x1000x2` | полотна 1×1 м, заповнюють простір між зовнішніми фризами |
| Профіль периметру `profile_canopy_perimeter_closed` | по краю покриття, зовнішньою гранню в лінію фриза |

## Довжини заготовок і щільність текстури

Розгортки деталей у GLB задають, що з чим робити:

| Деталь | Габарит | Розгортка | Як кладеться |
|---|---|---|---|
| `balk_150x150x1000`, `Lodge_20x200x1000` | 1 м | 1.0, але модель зроблена при 2.5 м і стиснена | відрізки ≤ 2.5 м |
| `Lodge_20x190x1000_bevel` | 1 м | 1.93 | дошки по 1 м |
| `ruberoid_1000x1000x2` | 1×1 м | 6.1 × 10.0 | полотна 1×1 м |
| `lodge_150x50x1000` | 1 м | 1.0 | цілою кроквою (несуча деталь, стик неприпустимий) |

Тому жодна деталь не розтягується більше ніж на ~13 % від своєї проєктної довжини, і напрямок
та щільність волокон лишаються такими, як задумав моделер.

## Припущення

- Габарити читаються по зовнішніх сторонах колон (у документації допускаються обидва варіанти —
  по зовнішніх габаритах і по центрах).
- Крок колон обмежений 3 м: 3 м дає 2 колони на сторону, 5 м — 3 колони, як у прикладі.
- Крокви розподіляються прольотами між осями колон, тому над кожною колоною крокви завжди є,
  а фактичний крок ≤ 500 мм.
- Виліт крокви за кільцеву балку взято як половину ширини балки (76 мм). Формулювання
  «виступає на половину за край кільцевої балки» допускає й половину ширини самого бруса (25 мм) —
  константа винесена в `config.js`.
